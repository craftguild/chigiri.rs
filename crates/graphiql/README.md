# GraphiQL assets

`chigiri_graphiql` is an internal, `std`-only asset provider. Axum and Hyper
adapters serve the view returned by `chigiri::Endpoint::graphiql()`. The
`graphiql` feature is disabled by default for the facade and bridges; the mock
server opts in explicitly. Applications must also call `.graphiql(true)` to
expose the UI and schema introspection.

## Ownership and updates

The handwritten inputs are the entry point, CSS, build script, package manifest
and lockfile, and license supplements under `frontend/`. `asset-inventory.json`
records every input and output path, output hash, size, MIME type, embedded
lookup table, and license entry. Only `assets/` is treated as third-party
generated output.
Unknown files, modified files, symlinks, and unregistered entries are rejected.

`src/embedded.rs` is generated by the asset build, but it is not covered by the
generated Rust exemption in ADR-0028. It remains subject to the 400-line limit.
If the entry point is split, update the inventory in the same change.

```bash
# Rebuild with the lockfile verified by Node 24.15.0 and npm 11.12.1.
python3 scripts/graphiql_build.py
python3 scripts/graphiql_build.py --check

# Validate ownership and the closed license set without Node.
python3 scripts/graphiql_inventory.py
python3 scripts/graphiql_inventory.py licenses
./scripts/check-implementation-rules.sh
```

Production builds use a temporary directory under `target/graphiql-assets/` and
run `npm ci --ignore-scripts`. The build requires zero npm-audit findings and
compares every byte of the esbuild output. Normal Cargo builds, consumers, CLI
startup, and UI requests require no Node, npm, CDN, or asset download. CI alone
uses the pinned Node toolchain for drift checks; it does not remove user files or
shared caches.

The asset set pins GraphiQL 5.4.0, `@graphiql/react` 0.39.0, React and
`react-dom` 19.2.8, GraphQL 17.0.2, Monaco 0.52.2, `monaco-graphql` 1.9.0, and
esbuild 0.28.2 in `package-lock.json`. The current inventory contains 42 files /
6,688,753 bytes, including notices. HTML is generated by the facade and is not
included in those figures.

## Connection and display contract

The UI sends JSON POST requests to the same-origin path with `Accept` and
`x-chigiri-preflight: 1` headers. It never derives the endpoint from query
parameters, `Host`, or `Forwarded`, and it never embeds environment values or
tokens in HTML. Headers, history, and settings remain in a page-local `Map`;
persistent header settings are not shown in the UI.

Workers use three pinned local module types. CSS uses a font-free public entry
point. The required Codicon font is embedded. The bundle adds no Roboto or Fira
assets, external plugins, telemetry, or WebSocket connections. Script, worker,
connect, and font sources
are restricted to the same origin. CSP permits only the inline styles required
by Monaco and Radix. The helper does not own authentication, CORS, or the
listener; applications apply authentication outside the route group or service.

## Licenses and approval records

`dependency-licenses.json` records the version, license, integrity, and actual
bundle inclusion of every lockfile dependency. `assets/THIRD_PARTY_NOTICES.txt` embeds the relevant notices and
is linked from the HTML license view. Four MIT packages without license text in
their tarballs use pinned source text from `frontend/license-supplements.json`.
The GraphiQL `doc-explorer` and `history` packages and
`react-compiler-runtime` use license text from their official repositories.
`react-remove-scroll-bar` 2.3.8 uses the official repository license at commit
`7301c160fda44cb8cf2b9fdfde61efad35736196` (2025-05-21); this records the text
source and does not claim independent release matching.

On 2026-09-09, the user explicitly approved `entities` 4.5.0 (BSD-2-Clause),
`tslib` 2.8.1 (0BSD), and `argparse` 2.0.1 (Python-2.0). That exception is
limited to those exact packages, versions, and licenses in `license-policy.json`.
MPL-2.0 remains a separate existing approval, subject to the same license,
notice, and acquisition checks.

Progress, automated checks, and manual UI verification are recorded in the
integrated validation record.
