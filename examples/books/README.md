# Books example

The repository [quick start](../../README.md#quick-start) explains how to check
generated drift, start the server, and reproduce POST Query/Mutation and GET
Query requests.

This example presents the following production path as one application.

```text
graphql/schema.graphql
  -> generated/books contract crate (ABI 8 complete traits / one application-error mapper)
  -> domain resolver + generated Resolvers assembly
  -> chigiri::Endpoint::builder (automatic safe baseline)
       -> explicit Stage A/B rate_limit
       -> typed inject (plugin / request ID / sampler / observer)
  -> immutable neutral Endpoint
  -> chigiri_hyper::service
  -> application-owned listener / route / signal / drain
  -> POST/GET /graphql + /readiness
```

The root `chigiri-books.toml` defines the inputs, generated crate, runtime, and
consumer checks. Run `chigiri rust --manifest chigiri-books.toml check` to verify
every generated byte, and run `update` with the same manifest after an SDL
change. After updating handwritten resolvers, use `doctor` to run a locked
compile of the actual consumer with its `production-validation` feature.

`tests/end_to_end.rs` uses real HTTP/1.1 connections on an ephemeral port to test
queries, mutations, validation errors, field errors, rejection of GET mutations,
and media negotiation.

The in-memory catalog limits titles and authors to 256 UTF-8 bytes each and
retains at most 1,000 books across requests. It returns
`CATALOG_CAPACITY_REACHED` when full. Without additional configuration,
`Endpoint::builder` applies bounded execution, caching, HTTP byte limits,
timeouts, CSRF protection, disabled introspection, and error masking. The
framework cannot infer an application identity for rate limiting, so this
example explicitly configures process-local keys for stages A and B. It also
connects request IDs, sampling, and lifecycle/error observers through typed
`inject`. A production application should impose capacity and quotas in its
persistent storage and use quota keys tied to authenticated tenants or users.

`Types` binds `Book` to `Arc<domain::Book>`. `QueryFields`, `MutationFields`, and
`BookFields` implement the complete generated traits with `CatalogError`.
`map_catalog_error` registers once at assembly start, exposing only the public
allowlist and preserving other errors as internal sources. There is no generated
output DTO or field-binding convention. See [Rust integration](../../docs/rust-integration.md).
