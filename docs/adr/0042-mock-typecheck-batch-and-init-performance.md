# ADR-0042: Batch Mock's independent module type checks

- Status: Accepted
- Date: 2026-09-16
- Implementation: Implemented (see the dedicated record for local validation)

## Background

A representative user SDL type-checks 22 resolvers and six hooks, each as an
independent module with an expected-type wrapper. The previous public-API path
loaded 167,427 bytes of shared host definitions from the built-in registry 56
times. The same input took 177 seconds in a debug build and approximately 15
seconds in a release build, making initialization appear stalled.

An experiment that added a reusable session and type-copy cache to a third-party
crate completed in under three seconds. It would, however, require retaining
about 22 MiB of pinned upstream source and following internal implementation
changes on every luaur update. Pythia instead removes duplicate work within the
published one-shot API and does not modify third-party source.

## Decision

1. Pythia combines the independent resolver and hook modules and their
   expected-type wrappers in one strict type-check source. Each source is
   enclosed in a uniquely named variadic function and a `do` scope so locals,
   `export type` declarations, and control flow cannot escape into another
   module.
2. Each user source is still compiled independently first. Batching must not
   accept attempts to escape the wrapper with an extra `end` or equivalent
   syntax. Both the standalone source and its expected-type wrapper are present
   in the batch.
3. The implementation calls the `check_with_definitions` API published by
   crates.io `luaur-rt 0.1.8` once for the complete set. It does not vendor
   `luaur-rt` or `luaur-analysis`, or modify their source, manifests, or type
   copier.
4. For every source, the batch records its byte range, original starting line,
   and wrapper prefix. The first diagnostic is mapped back to the resolver ID or
   hook slot and a bounded original-module line location. User source text is
   not copied into ordinary diagnostics.
5. Total candidate coverage and the existing logical byte capacity are checked
   before starting the compiler and type checker. The existing process gate is
   held for the single native check. Cancellation checks before and after it,
   per-module VM initialization, readiness, and runtime VM isolation remain in
   place.
6. `init` displays four processing stages and elapsed time only when stderr is a
   TTY. Stdout, non-TTY output, project formats, and generated bytes do not
   change. Only the first-pass StyLua/full_moon development profile is
   optimized.

Handwritten Pythia code continues to use `forbid(unsafe_code)`. The repository
does not add a crate that directly wraps `luaur-analysis` raw-pointer APIs or a
fork of third-party source. If luaur later publishes a safe multi-module or
session API, adoption still requires preservation of module isolation,
diagnostic locations, capacity bounds, and cancellation behavior.

## Verification and maintenance

Regression tests include valid modules that reuse the same local and exported
type names and an invalid module that tries to reference another module's type.
They cover standalone compilation, expected-type incompatibility, coordinates
and line mapping for a later resolver, hooks, capacity, cancellation, VM
initialization, and project, bundle, and runtime behavior. Debug and release
measurements use the same SDL in independent processes, and record cold and
subsequent attempts separately. See the
performance validation record for results.
